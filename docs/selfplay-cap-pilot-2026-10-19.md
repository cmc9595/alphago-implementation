# 32판 탐색량 배분·시간 측정 (2026-10-19)

사용자 요청: 먼저 32판을 만들고 실제 소요 시간을 확인한다. 학습·자동 승급은 하지 않는다.

- 생성 모델: checkpoints/shared_supervised_6x96_20261018/best.pt (24,000스텝). 동일 공유 객체를 정책·가치 평가에 사용한다.
- 매 수 독립적으로 확률0.25로400회, 나머지는100회 탐색. 배치32. 트리는 실제 착수마다 새로 시작한다.
- 400회 수: 루트 Dirichlet(alpha0.03, fraction0.25), 첫30수 온도1/이후0.2.
- 100회 수: Dirichlet 없음, 방문수 최대인 수 선택(온도0).
- 19x19, 덤7.5, positional superko. 기권 없음. 연속 두 패스로 종료. 600수 상한 종료 및 판정 실패 판은 학습 대상 제외.
- GNU Go level10 중국식 판정, GTP 명령별30초 제한. 사석·소유권 저장.
- 원본 NPZ에는 재현·진단을 위해 전 수의 feature/방문분포/방문수/착수를 보관한다. train_mask=True인400회 국면만 SearchData.rows에 포함한다. 100회 국면은 저장되어도 학습용으로 선택하지 않는다.
- 판별 seed 고정. 완료된 NPZ+JSON은 재사용하고 중단된 미완료 판만 처음부터 다시 생성한다. 모델/코드/설정 해시가 달라지면 재개를 거부한다.
- 단일 생성 프로세스. CPU4스레드/interop2/MPS메모리비율0.12, 기존 RSS8GiB 및 시스템 가용10% guard. 판마다가 아니라10수마다 메모리 확인. 기존 실험 잠금과 충돌하면 즉시 실패한다.
- 실시간 바둑판 분석은 시작 시 비활성이었음. 측정 중 사용자가 다른 GPU 작업을 실행하면 소요 시간에 영향이 생길 수 있다.

## 기록

runs/experiments/selfplay_cap_400_100_20261019/

- manifest.json: 모델·코드 해시와 설정
- state.json: 현재 판/수, 완료 판 수, 유효 판정/제외 판, 학습 가능 국면 수
- game_000.npz + .json + .sgf: 판별 데이터, 생성·판정 시간 및 탐색량, 기보
- summary.json: 32판 완료 후 평균/중앙값 판당 시간, 전체 탐색 횟수, 유효 학습 국면 수
- runner.log: 판 완료 로그 및 오류

시간은 GPU 워밍업·모델 로딩을 제외하고, 각 판의 feature 추출·MCTS·GNU Go 프로세스 생성·판정·종료를 포함한 monotonic 경과 시간이다. NPZ 압축 및 디스크 저장은 판별 측정 구간 밖이다. 절전 등으로 측정이 변할 수 있으며 GPU 커널 순수 실행 시간으로 해석하지 않는다.

진행률 (기록만 읽음; 학습/생성 시작 안 함):

```sh
.venv/bin/python scripts/selfplay_cap_pilot.py --watch
```

생성/중단 후 재개:

```sh
.venv/bin/python -u scripts/selfplay_cap_pilot.py
```

검증: tests/test_search_caps.py + test_search_learning.py + test_shared_training.py 12개 통과. 400/100 실제 방문수, 빠른 탐색의 노이즈 비활성, full mask에 따른 학습 대상 제외, 구형 mask 없는 데이터 호환을 포함한다.
