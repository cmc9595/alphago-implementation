# 10만 판 replay 풀: 3회 시험 운영

실행 이름: `replay_pilot_1200v_p06_20261120`. 이 실험은 무한 실행하지 않으며 3회 후 종료한다.

## 탐색 설정 변경 기록

사용자 요청으로 2·3회차 학습용 탐색을 **1,600회**로 변경했다. 나머지 200회·6%는 유지한다.
1회차 완료 결과는 변경하지 않는다. 진행 중이던 2회차 1,200회 기보와 작업 기록은 보존하고,
새 seed 21050000 / 21150000 및 `_v1600` 별도 생성 폴더로 재개한다.
실행 이름과 최초 config는 역사 기록으로 유지하며, 이후 설정은 `search_schedule.json` 및
회차별 `context.json`에 기록한다. 이미 시작한 회차의 frozen context 변경은 거부한다.
중단된 1,200회 2회차 일부 기보는 보관만 하며 활성 풀에 자동 편입하지 않는다.

## 설정

| 항목 | 설정 |
|---|---|
| 초기 기준 모델 | `checkpoints/depth_gpool_6x96_20261117/final.pt` |
| 반복당 신규 대국 | 2,000판, 총 3회 |
| 학습용 수 | 6%, MCTS 1,200회 |
| 나머지 수 | MCTS 200회, 트리 재사용 |
| 포석 다양화 | 처음 30수 방문 비율 샘플링, 루트 잡음은 기존 생성 코드 유지 |
| 기권 / 제한 | 기권 없음 / 600수, 미완성·판정 실패 제외 |
| 신규 seed | 1회 20900000, 2회 21000000, 3회 21100000부터 각 2,000개 |
| 훈련 풀 | 최근 최대 100,000개의 유효·고유·비검증 대국 |
| 정책 정답 | 5라운드 이후의 학습용 탐색 방문 분포 |
| 가치·소유권 | 3라운드 이후의 유효 대국, 최종 승패 ±1 / 최종 소유권 |
| 샘플링 | 최신 묶음 50% + 이전 풀 50%, 각 층에서 대국 균등 선택 후 국면 하나 |
| 배치 / 갱신 | 배치 64, 반복당 1,000스텝, 증강 8대칭 |
| 가치 학습 | 각 추출 시 50% 마스크, Q 혼합 없음 |
| optimizer | SGD momentum 0.9, Nesterov, 행렬 weight decay 1e-4, 고정 lr 0.0002 |
| 정규화 | 기존 학습처럼 BN running statistics 고정 |

이는 파일럿 시작 설정이지 검증된 최적값이 아니다. 최신 묶음에 포함된 대국도 훈련·검증 분할을 적용한다.
매 배치에서 최신 32판과 과거 32판은 각각 중복 없이 추출한다. 긴 대국이나 학습용 국면이 많은 대국에
더 높은 추출 확률을 주지 않는다. 다른 스텝에서는 같은 대국의 다른 국면을 뽑을 수 있다.

## 데이터 관리 및 검증 격리

- 기존 3~7라운드와 파일럿의 새 대국을 목록으로 관리한다. 원본은 삭제·이동하지 않는다.
- 정확히 동일한 수순은 최신 기록 하나만 유지한다. 회전·반사·수순 전환으로 같은 국면이 되는 경우까지 합치지는 않는다.
- 기존 고정 1,000판은 기보 해시로 모든 출처에서 영구 제외한다.
- 추가로 기보 해시를 이용해 약 5%를 내부 검증으로 영구 분류한다. 창에서 빠졌다 들어와도 학습으로 바뀌지 않는다.
- 내부 모니터링용 최대 500판과 해당 학습용 국면은 1회 차에 동결한다. 후속 반복에서 검증 대상이나 정답이 바뀌지 않는다.
- 기존 모델이 과거 학습한 대국이 내부 모니터링셋에 포함될 수 있다. 이를 독립적인 최종 테스트로 해석하지 않는다.
- `runs/replay_cache_v1/`에는 학습용 국면만 bit-pack한 작은 캐시를 보관한다. 원본 수정 시 다른 캐시 키를 사용한다.
- 훈련은 최대 256판 LRU 캐시로 읽는다. 전체 10만 판 특징을 RAM에 올리지 않는다.
- 브라우저 대국·사람 기보·기존 AlphaGo 방식 가치 생성 데이터는 이번 풀에 자동 편입하지 않는다.

## 후보 평가와 승격

1. 내부 모니터링: 250스텝마다 정책 CE·일치율·가치/소유권 MSE 기록.
2. 기존 고정 1,000판: 기준 모델과 후보의 직접 가치 MSE 비교. 참고 지표이며 승격을 단독 결정하지 않는다.
3. T5 참고 분석: 1,600회 탐색 비교. 단일 문제로, 완전한 사활 시험 모음은 아직 아니다.
4. 기준 모델과 흑백 교대 100판, 양쪽 MCTS 400회.
5. 유효 95판 이상이고 후보 점수율 50% 이상이면 **별도 포석의 고정 200판**을 추가한다.
6. **독립적인 200판만** 확인 시험으로 사용: 유효 190판 이상, 완성된 흑백 쌍 95개 이상,
   Wilson 및 쌍별 bootstrap 95% 구간 하한이 모두 50%를 초과할 때 승격한다.

확인 시험 도중 결과를 보고 조기 승격하지 않는다. 100판 선별과 확인 200판을 합쳐서 선택 편향이 있는
확인 통계로 사용하지 않는다. 3회 시험의 반복적 후보 선택과 제한된 상대 평가라는 한계가 있어 일반 기력의 증명은 아니다.
미승격이면 기존 기준 모델을 유지하고, 생성된 새 데이터는 풀에 남긴다. 승격된 모델만 다음 생성에 사용한다.
후보 학습은 기준 모델에서 시작한다. 기준 모델에 replay optimizer 상태가 있으면 이어받으며,
탈락 후보의 가중치·optimizer는 다음 후보에 이어주지 않는다.

## 실행·진행·재개

저장소 루트에서:

```bash
caffeinate -i .venv/bin/python -u scripts/replay_loop.py
.venv/bin/python scripts/progress_replay.py --watch
```

현재 반복의 상세 생성 진행은 표시된 selfplay run 이름으로 기존
`scripts/progress_selfplay_parallel.py <run> --watch`에서도 확인할 수 있다.

- 설정·단계·생성 모델 해시·캐시 목록·학습 상태·평가 결과: `runs/replay/<실행 이름>/`
- 생성 기보: `runs/experiments/<실행 이름>_selfplay_c01/` 등
- 훈련 체크포인트: `cycle_01/train/{last,final}.pt` 등. optimizer, NumPy/Torch/MPS RNG,
  스텝, 표본 추출 횟수까지 저장해 같은 설정으로 재개한다.
- 중단 후 같은 명령을 실행하면 완료한 단계는 재사용한다. 설정이나 frozen 생성 모델이 달라지면 거부한다.
- GPU 자식 작업은 한 번에 하나. controller 잠금으로 중복 파일럿 실행을 막는다.
- 시작 시 디스크 15 GiB 미만, 진행 중 10 GiB 미만이면 중단한다. 기존 self-play/trainer 메모리 보호도 유지한다.
- 파일럿은 바둑판 모델이나 Git을 자동 변경하지 않는다. 바둑판의 별도 분석은 GPU 자원을 함께 사용하므로 속도에 영향을 준다.
