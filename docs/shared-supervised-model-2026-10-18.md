# 기존 정답 자료로 공유 정책·가치·소유권 모델 만들기

사용자 요청: 기존 사람 기보와 생성 가치망 자료를 사용해 공유 모델을 새로 만들고 기존 두 망 엔진과 비교한다. 새 MCTS 기보 생성이나 기존 망 출력 모방을 필요로 하지 않는 다중 과제 지도학습이다.

## 구조와 초기화

- 34×19×19 입력, 6블록·96채널의 기존 GoNet.
- 공통 stem/trunk에서 정책362개 logits, 가치tanh scalar, 소유권19×19 출력으로 분기.
- 기존 SL final.pt의 stem/trunk/정책/가치 가중치에서 초기화. 소유권 head만 무작위 초기화.
- 기존 value_own 가중치를 이식하지 않는다. 서로 다른 trunk에 학습된 head를 바로 붙여 같은 의미가 유지된다고 가정하지 않는다. 기존 value_own은 기준 평가에 사용한다.
- 8765/8766 및 기존 체크포인트는 유지. 신규 후보 자동 적용 없음.

## 데이터와 한 번의 업데이트

사람 데이터 data/kgs.npz + data/fox_dan.npz에서32국면, 생성 data/value/gen/batch_*.npz에서32국면을 뽑아64국면을 한 배치로 처리한다.

- 사람32국면: 실제 착수에 대한 cross entropy만 계산. 사람 기보의 승패·소유권 정답은 이 실험에서 사용하지 않는다.
- 생성32국면: 최종 GNU Go 승패에 대한 가치MSE와 소유권MSE만 계산. 실제 RL착수는 정책 정답으로 사용하지 않는다. MCTS방문분포도 이 자료에는 없다.
- 합산손실 = 사람정책CE + 생성가치MSE + 0.5×생성소유권MSE.
- 합산한 손실을 한 번 역전파해 optimizer를 한 번 실행한다. 각 데이터로 trunk를 따로 번갈아 업데이트하는 구현이 아니다.
- 사람·생성 양쪽에 회전/반사 증강을 적용. 생성가치/소유권은 국면 착수자 관점으로 변환한다.
- 가치라벨0(불명)은 가치손실에서 제외한다.

## 학습 설정

- run: shared_supervised_6x96_20261018.
- 총30,000 optimizer step. 출처당32개이므로 사람960,000개와 생성960,000개, 합계1,920,000개 표본 제시. 서로 다른 국면 수와 같다는 뜻은 아니다.
- 처음500스텝은 stem/trunk와 정책head를 고정하고 가치·소유권head만 적응시킨다. 501스텝부터 전부 업데이트.
- SGD momentum0.9/Nesterov, weight decay0.0001(행렬파라미터만), normclip5.
- trunk·정책head lr0.001, 가치·소유권head lr0.003, 워밍업 이후 cosine으로10%까지 감소.
- 기존 BatchNorm running_mean/variance는 전 기간 고정. 활성화된 affine파라미터는 학습한다. 이전 작은 기보 실험의 통계 변화와 충격을 줄이기 위한 선택이며 최적값이라고 주장하지 않는다.
- 생성 자료는 약24.8만판의 기존 판당3국면 자료만 사용한다. 과거RLarchive/사람승패 자료는 가치 학습에 추가하지 않는다. 기존 GNU Go라벨과 일부 상한종료 기보가 포함된 자료를 재사용하므로 완벽한 정답을 주장하지 않는다.
- 소유권손실0.5는 기존 별도가치망1.5와 다른 실험설정이다. 두 주요과제의 보존을 우선한 시작값이며 구조공유만의 인과효과를 증명하는 통제실험은 아니다.

## 검증과 후보 선정

사람자료는 기존SL의 판 단위2%분리를, 생성자료는 기존ValueData의 판 단위3%분리를 그대로 유지한다. 고정8192개씩을 저장해 기존SL정책+별도가치망, 최초공유모델, 학습공유모델을 동일한 국면에서 비교한다.

- 정책정확도/CE, 생성가치MSE/승패정확도, 수순별가치MSE, 소유권MSE 기록.
- 검증자료는 과거모델선정에 쓰인 분리를 재사용하므로 완전히새로운최종test가 아니다.
- 후보점수는 정책CE/기준CE + 가치MSE/기준MSE, 정책정확도가기준보다0.5%p이상하락하면추가패널티를 준다. 두과제를모두보려는운영선택이며기력보장은아니다.
- 매100스텝 last.pt 원자적저장, 매1000스텝고정검증과best.pt선정. optimizer/RNG복원, 설정/데이터/코드해시가다르면재개거부.
- 작은검증지표변화만으로승급하지않으며, 최종적으로대국비교한다.

## 속도·기력 비교

학습프로세스종료후별도프로세스로실행해메모리를회수한다.

1. 기존SL+value_own두망대공유망: 동일한8개실제국면,batch32추론과MCTS400회. 단일공유NetEvaluator가신경망을한번만호출하는지테스트한다. 순서를번갈아실행하되GUI동시사용영향이남을수있다.
2. 기존분리망대공유망: 양쪽400회,batch32,10개포석흑백교대20판. GNU Go계가/상한Void. 동일시간으로실험조건을바꾸지않는다.
3. 20판은선별용이다. 속도가빨라져도동일횟수기력이보존된다고가정하지않고, 유망하면대국수를늘리는다음단계로진행한다.

scripts/match.py에batch옵션을추가했으며기존기본값16은유지한다. 공유망비교에서는value경로를따로넘기지않아동일객체를사용하도록한다. 동일파일을두번로드해trunk를두번평가하는실수를피한다.

## 실행과 진행률

```sh
.venv/bin/python scripts/progress_shared.py --watch
```

전체파이프라인실행/재개:

```sh
.venv/bin/python scripts/run_shared_pipeline.py
```

첫실행을백그라운드로등록했다. runs/experiments/shared_supervised_6x96_20261018/pipeline.json과state.json을구분해파이프라인단계/학습진행을기록한다. 모델은checkpoints/shared_supervised_6x96_20261018/에저장한다. 속도는speed.json, 대국은runs/matches/shared_supervised_6x96_20261018_vs_separate_400/에저장한다.

기존학습의파일잠금과충돌하면기다린다. CPU RSS8GiB점검, MPS비율0.12, 단일GPU학습프로세스를유지한다. 주기점검이시스템전체OOM방지를보증하지는않는다.

검증: 관련자동테스트16개통과. 출처별손실마스킹, head워밍업과공동trunk업데이트, BN통계고정, 공유MCTS의1회추론, 동일배치대국옵션을포함한다.

전용진행률스크립트scripts/progress_shared.py는표준라이브러리만사용하고기록만읽는다. 화면은기본2초마다갱신하며학습MSE/정책CE·정확도/소유권MSE, 검증평가스텝·단계별MSE·기준분리망대비변화, 최근본학습10개기록의평균속도와Asia/Seoul종료시각을표시한다. 학습종료ETA는향후검증/속도측정/20판평가를제외하며, 대국단계에서는완료된대국의실제벽시계시간으로별도ETA를표시한다. 프로세스종료/갱신지연시ETA를보류한다. 이미실행중인학습프로세스는재시작하지않았다.
