# 전체 풀 균등 추출 + 누적 학습, 5,000판 묶음

사용자 요청으로 기존 최신/과거 50:50 방식과 승격 실패 시 학습 초기화 방식을 변경했다.
새 실행: `replay_continuous_1600v_p06_5000_20261121`. **3회 시험 후 종료**한다.

## 2026-11-22 탐색 설정 변경

사용자 요청으로 **다음 생성인 3회차부터 학습용 25%는 1,000회, 나머지 75%는 200회**로 변경한다.
이미 완료된 1·2회차의 1,600/200회·6% 기보와 학습·평가 기록은 그대로 유지한다.
최초 실행 이름/config는 역사 기록이며, 후속 조건은 `generation_schedule.json`과 회차별 context에 고정한다.
3회차는 `_v1000_p25` 별도 생성 폴더와 seed 22350000을 사용한다. 5,000판·전체 풀 대국 균등 추출·
누적 학습/생성 모델 분리·승격 기준은 변경하지 않는다. 이는 초기 KataGo 논문의 full/fast 비율과
횟수에 맞춘 것으로, 탐색 노드 상한 등 KataGo의 전체 구현을 동일하게 재현했다는 뜻은 아니다.

같은 날 사용자 요청으로 **3회차 학습부터 가치 마스크를 100%**로 변경했다.
`training_schedule.json`에 기록하고, 학습 시작 시 `training_context.json` 및 checkpoint signature에 고정한다.
앞선 회차는 50%로 남겨 두고 기존 기록을 변경하지 않는다. 현재 1,000스텝·배치 64라면 가치 학습도
64,000개 추출 표본에 적용한다. 스텝 간에는 동일 대국/국면을 다시 뽑을 수 있다.
전체 10만 판을 중복 없이 한 번씩 훑는 epoch 방식은 **아직 적용하지 않았다.**

이후 사용자 승인으로 3회차 학습 예산을 **배치 512 × 250스텝(128,000국면 추출)**으로 변경했다.
가치 마스크 100%·학습률 0.0002는 유지하고, 지표와 재개 checkpoint는 50스텝마다 저장한다.
기존 1·2회차는 배치 64 × 1,000스텝 기록을 유지한다. M1 Max 측정 범위에서 배치 512의 실제
학습 처리량이 가장 높았지만, 이것이 더 높은 기력이나 일반화를 보장하지는 않는다.
반복 추출이므로 128,000개의 고유 대국/국면을 의미하지 않으며, 업데이트 횟수도 이전과 다르다.

## 변경 사항

| 항목 | 기존 파일럿 | 새 실행 |
|---|---|---|
| 생성 묶음 | 2,000판 | 5,000판 |
| 추출 | 최신 50% + 과거 50% | 활성 10만 판에서 대국 균등 추출 |
| 학습 모델 | 승격 실패 시 기준 모델에서 다시 출발 | 직전 학습 모델·optimizer·RNG를 계속 이어받음 |
| 생성 모델 | 승격할 때 변경 | 동일: 승격할 때만 변경 |
| 탐색 | 최근 설정 1,600/200회·6% | 그대로 유지 |

정확히는 **대국을 균등 선택한 뒤 해당 대국의 학습용 국면 하나를 선택**한다.
AlphaGo Zero/KataGo 논문의 국면 균등 추출과 완전히 같은 방식은 아니다.
한 배치에서 대국은 중복되지 않는다. 최신 대국을 별도로 더 자주 뽑지 않는다.
1,000스텝 × 64 = 64,000국면 추출이므로, 한 학습 구간에서 10만 판 전체를 한 번씩 훑는 방식은 아니다.

## 학습·생성 모델 분리

```
생성 모델 ──5,000판 생성──> 데이터 풀 갱신
                              ↓
누적 학습 모델 ──1,000스텝 학습──> 새 학습 모델
                              ↓ 평가
                    통과하면 생성 모델도 교체
                    탈락해도 학습 모델은 다음 학습으로 계속
```

학습은 SGD momentum 0.9/Nesterov, lr 0.0002 고정, 배치 64, 250스텝마다 저장한다.
종국 승패 ±1, 가치 마스크 50%, 소유권 weight 0.5, Q 혼합·사람/생성 anchor 배치 없음.
정책은 5라운드 이후, 가치·소유권은 활성 풀의 모든 적합 라운드를 사용한다.
확인 대국의 승격 기준은 기존과 같다. 후보 학습이 누적되더라도 실제 기력이 계속 좋아진다는 보장은 없다.
따라서 3회로 제한하고 NaN/무한대 손실·메모리·디스크 오류는 중단한다.

## 기존 작업 이어받기

- 기존 파일럿의 완료된 회차 결과와 기보를 변경하지 않는다.
- 기존 2회차 학습 후보를 누적 학습 시작점으로 복사한다. optimizer도 이어받는다.
- 생성 시작점은 기존 파일럿의 기준 모델이다. 탈락 후보를 생성에 쓰지 않는다.
- 생성 중이던 기존 3회차 `_selfplay_c03_v1600`은 동일 seed·모델 가중치·탐색 설정을 확인한 후
  **2,000판 목표를 5,000판으로 확장**한다. 완료한 판은 건너뛰고 새 판만 생성한다.
- 변경 전 manifest를 새 실행의 `cycle_01/first_batch_manifest_before_extension.json`에 보존한다.
- 다음 묶음은 새 디렉터리와 seed 22200000, 22300000을 사용한다.
- 기존 완료 1·2회차 기보도 replay 풀에 포함한다. 중단된 1,200회 2회차 일부 기보는 자동 편입하지 않는다.

## 격리·재개·진행

- 기존 고정 평가 1,000판과 해시 기반 내부 검증은 계속 학습에서 제외한다.
- 내부 모니터링 500판도 기존 파일럿과 동일하게 동결해 비교 가능하게 유지한다.
- 오래된 데이터는 활성 목록에서만 빠지며 원본 파일을 삭제하지 않는다.
- 중단 후 같은 명령으로 재개하면 모델·optimizer·난수·스텝을 복원한다.
- 모델 SHA256·학습 입력·pool 목록·생성 조건이 바뀌면 기존 회차를 덮어쓰지 않고 오류로 중단한다.
- 학습 시작 시점, 완료 시점, 생성 모델과 누적 학습 모델 경로를 각각 state와 context에 기록한다.

```bash
zsh pipelines/continuous_replay.sh
.venv/bin/python scripts/progress_replay.py --watch
```

진행 스크립트의 기본 실행 이름은 새 실행으로 변경했다. 기존 파일럿을 보려면:

```bash
.venv/bin/python scripts/progress_replay.py replay_pilot_1200v_p06_20261120 --watch
```

누적 replay 스텝은 이전 후보부터 이어받은 이력만 센다. 과거에 탈락해 버려진 다른 후보들의
학습까지 소급해 합쳤다는 뜻은 아니다. 바둑판 모델은 자동으로 교체하지 않는다.
