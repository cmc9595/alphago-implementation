# 구축 계획

목표: 2016년 AlphaGo 파이프라인(SL 정책망 → RL 정책망 → 가치망 → MCTS)을
Apple M3 Pro 맥북 한 대로 축소 재현해 19줄 아마추어 수준(초단 전후)에 도달.

## 최종 구현 범위 (2026-10-18 사용자 확정)

초기 재현 엔진은 **SL 정책망 + RL 대국 데이터로 학습한 별도 가치망 + MCTS**이다.
빠른 롤아웃 정책 및 롤아웃 혼합 평가는 구현하지 않는다.

2026-10-18 추가 사용자 요청으로 **MCTS 자가대국의 방문 분포와 종국 승패를 이용해 정책망·가치망을 모두 업데이트하는 확장 실험**을 진행한다. 이 실험에는 앞서 정한 SL 가중치 고정 제한을 적용하지 않는다. 별도 정책·가치 구조를 유지하고 처음에는 400회 탐색으로 작게 검증한다. 현재 바둑판은 기존 모델을 유지하며 신규 후보를 자동 배포하지 않는다.

설정·범위·진행률: docs/search-policy-iteration-2026-10-18.md. 바둑판에는 6400회, 12800회 및 연속 탐색이 이미 구현되어 있다.

## 초기 재현 전략 (아래는 기존 AlphaGo 단계의 기록)

1. **AlphaZero가 아니라 AlphaGo 방식.** RL 단계가 MCTS 없는 정책망끼리 대국(REINFORCE)이라
   배치 forward 한 번으로 수백 판을 동시에 진행할 수 있다.
2. **실력의 대부분은 SL에서.** 고단자 기보 지도학습이 아마추어급의 바탕.
3. **MCTS prior는 SL 정책망**(원 논문과 동일). RL 정책망은 가치망 학습용 대국 생성기.
4. **축(ladder) 특징 등 수작업 특징**으로 작은 망의 약점(수읽기)을 보완.
5. **보드 로직은 C++**(이 저장소의 `engine/`)로 CPU 병목 제거.

## 마일스톤

| 단계 | 목표 | 측정 |
|---|---|---|
| M1 | SL 정책망 단독 5~1급 | 검증 정확도 ≥ 48%, GNU Go 상대 ≥ 90% |

## 0주차 벤치마크 결과 (M3 Pro 18코어 GPU, 36GB, torch 2.14 / mlx 0.32)

`python scripts/bench.py`로 재현. 학습 샘플/s는 batch 256 기준이고, 추론은 batch 16 기준(GPU→CPU 복사 포함).

| 모델 (blocks×ch) | MPS fp32 학습 | MPS 추론 | MLX 학습 | 30M 국면 × 3 epoch |
|---|---|---|---|---|
| 6×96 | **1,466/s** | 4,965/s | 510/s | **약 17시간** |
| 8×128 | 712/s | 2,423/s | 248/s | 약 35시간 |
| 10×128 | 568/s | 1,977/s | 204/s | 약 44시간 |
| 12×192 (AlphaGo 규모) | 241/s | 812/s | 89/s | 약 104시간 |

- CPU(6×96): 학습 161/s로 MPS보다 9배 느림.
- 엔진 특징 추출: 1스레드 약 2.1만 국면/s, 전체 코어 약 11~14만 국면/s → GPU 병목이 아님.

결론:
- **PyTorch MPS fp32로 확정.** MLX는 학습이 약 3배 느리고, bf16 autocast는 MPS에서 이득이 없다.
- **SL은 6×96으로 시작**(하루 이내)하고, 결과가 좋으면 8×128을 추가로 학습.
- RL 자가대국 예상: 6×96 추론 약 5천 국면/s → 512판 × 250수 ≈ 26초, **시간당 약 6~7만 판**(계획 추정치의 2배).
- MCTS 예상: 6×96으로 1수당 1,600 플레이아웃 ≈ 0.3~0.4초.

### 메모리 주의 (실제로 맥북이 꺼졌던 원인)

이 맥은 swap이 0이라, 메모리가 넘치면 바로 다운된다. 첫 번째 벤치마크는 MPS, MLX, CPU와
12×192 모델을 한 프로세스에서 연달아 돌리다가 OOM으로 맥북이 꺼졌다. 이후 원칙:
- GPU 작업은 케이스별로 프로세스를 분리하고, 결과는 단계마다 즉시 저장.
- `PYTORCH_MPS_HIGH_WATERMARK_RATIO=0.3`과 `PYTORCH_MPS_LOW_WATERMARK_RATIO=0.25`를 함께 설정
  (high만 낮추면 low 기본값과 충돌해 에러), MLX는 `mx.set_memory_limit` 사용.
- 장시간 학습 스크립트에도 같은 상한을 적용하고, 체크포인트에서 재개 가능하게 구현.

## RL 자가대국 종료와 계가 규칙 (결정: 2026-10-14, 방안 C)

- 대국 중에는 정책망이 원하는 때 패스할 수 있다(사람처럼 패스하는 습관 유지).
- 연속 2패스가 나오면 **정리 단계**로 넘어간다. 패스를 금지하고(둘 곳이 없을 때만 패스),
  사석을 실제로 따낼 때까지 더 둔 뒤 Tromp-Taylor로 계가한다.
- **정리 단계의 수는 학습에 쓰지 않는다.** 승패 판정에만 쓴다. REINFORCE 궤적과
  가치망 국면은 정상 구간(첫 2패스까지)에서만 뽑는다. 그러지 않으면 정책망이 패스를 안 하는 습관을 배운다.
- 진단 지표로, 정리 전후로 승패가 뒤집힌 비율을 기록한다.
- GTP에 `kgs-genmove_cleanup`을 지원해서, 다른 엔진이나 서버와 사석 분쟁이 생겨도 같은 로직으로 처리한다.
- 선택 이유: 승패 라벨의 잡음이 줄어 RL 학습 효율이 좋아진다(A안 대비).
  대신 봇이 스스로 사석을 따내는 습관은 생기지 않으므로, 사람과 둘 때의 깔끔한 종료는 UI의 사석 합의 기능으로 처리한다.

## RL 1차 실행 붕괴와 대응 (2026-10-14)

- 설정은 원 논문 그대로: SGD lr 1e-3, 기울기 클리핑 5, 기준선으로 쓰는 가치 head가 trunk까지 학습.
- 100번째 반복에서 SL 상대 73%로 순조로웠다. 그런데 157~181번째 반복에서 승률이 75%에서 6%로 붕괴했다.
- 원인: 패스 확률이 줄어드는 악순환. 둘 곳이 없어도 계속 두다 보니 자기 집을 메워 대마가 죽고,
  대국 대부분이 400수 상한에 걸렸다(256판 중 201판).
- 대응:
  - SL 정책 기준 KL 제약(β=0.1)
  - lr 5e-4
  - 가치 head는 분리된 trunk 특징만 읽음(trunk는 정책 학습으로만 바뀜)
  - 50번 반복마다 SL과 평가하고, 최고치보다 15%p 떨어지면 최고 시점으로 자동 복구하고 lr을 절반으로
  - 학습 중인 망의 패스 비율과 상한 도달 판 수 지표 추가
- 붕괴한 실행은 `checkpoints/rl_6x96_collapsed/`에 보관.

## 계가: GNU Go 판정관 도입 (2026-10-14)

- 정리 단계 계가에서 결함이 발견됐다. 사람 대국에서 수비 쪽이 사석 무리에 돌을 덧붙이면 끝까지 잡히지 않았다.
  SL 정책은 사석을 확실히 잡아내는 수를 거의 배우지 않았기 때문이다.
  GNU Go 판정과의 승패 일치율은 83%였다.
- RL 220번째 반복부터 **GNU Go(level 5, 프로세스 10개 병렬)가 승패를 판정**하도록 바꿨다.
  각 돌 무리의 사활을 직접 읽어서 판정하고, 256판에 약 13초가 걸린다. 정리 단계는 판정이 실패했을 때만 쓰는 예비 수단이다.
- 매 반복의 자가대국을 `checkpoints/rl_6x96/games/iterNNNNN.npz`에 보관한다.
  수순, GNU Go 점수, 점마다의 최종 소유권이 들어 있고, 이후 가치망과 **소유권 head** 학습에 쓴다.
- 브라우저 바둑판도 대국이 끝나면 GNU Go 판정 결과를 보여 주고 사석을 ×로 표시한다.

## KL 기준 교체 (2026-10-15, 1540번째 반복)

- 정체 확인: 500번째 반복 이후 SL 상대 평가가 66~70%에 머물렀다.
  상대별 승률을 보면 iter800 이후의 스냅샷 상대로는 50~52%로, 향상이 거의 없었다.
  KL(SL 기준)은 700번째 반복부터 0.010 근처에서 포화됐다.
- 조치: ProRL 방식을 따라 KL 기준을 원래 SL에서 **1540번째 반복의 RL 가중치**(`klref_iter1540.pt`)로 옮겼다.
  붕괴를 막는 제약은 유지하면서 기준점만 앞으로 옮긴 것이다. 평가와 자동 복구 기준은 그대로 원래 SL 상대 승률이다.
- 판단 기준: 몇백 번 반복 안에 SL 상대 평가가 70%를 확실히 넘거나, 최근 스냅샷 상대 승률이 다시 55% 이상으로 벌어지면 효과가 있는 것이다.

## 대국과 판정 겹치기 (2026-10-15, 2210번째 반복부터)

- GPU가 k+1번째 묶음을 두는 동안, GNU Go가 CPU에서 k번째 묶음을 판정한다.
  그래서 k+1번째 묶음은 한 번 덜 업데이트된 정책으로 둔다(지연 1회, 학습률이 작아 영향 미미).
- 반복당 시간이 약 40초에서 약 29초로 **약 28% 단축**됐다. 판정 대기 시간은 0초.
- GNU Go 판정관 풀을 블로킹 큐로 바꿨다. 학습 묶음과 평가가 동시에 판정을 요청해도 실패하지 않고 기다린다.
- `--no-pipeline`으로 끌 수 있다. 가치망 데이터 생성에도 같은 구조를 쓴다.

## RL 결과 (rl_6x96, 2026-10-16)

- 3,000번 반복 × 256판(GNU Go 판정분 71만 판 저장, 299MB), 약 33시간(붕괴 재시작과 이동 중 잠자기 포함)
- 학습 중 평가(128판, SL 상대) 500번 반복 구간 평균:
  61% → 68% → 69% → **75%**(KL 기준 교체) → 78% → **81%**
- 마지막 단계 상대별 승률: SL 79%, iter200 72%, iter800 64%, iter1600 59%, iter2400 51%, iter2800 50%
- 자동 복구는 한 번도 작동하지 않았다. 마지막 100번 반복: 패스 1.2%, 상한 도달 1.4판, KL 0.007, 가치 MSE 0.717
- **정밀 평가 (512판, 샘플링 대국, GNU Go 판정)**:

| A | B | A 승률 (95% 구간) |
|---|---|---|
| RL 최종 (3000) | SL | **79.1%** (75.6–82.6) |
| RL 최고 기록 (2550, 학습 중 평가 85.9%) | SL | 78.5% (75.0–82.1) |
| RL 2300 | SL | 76.2% (72.5–79.9) |
| RL 최종 | RL 2550 | 49.0% (44.7–53.4) → 동급 |

- 학습 중 "최고 기록" 85.9%는 128판 평가의 운이 섞인 값이었다. **가치망 데이터 생성에는 RL 최종(3000)을 쓴다.**
- 탐색 없는 정책 대국 (최선의 수만 둠, 초반 6수 무작위 + 흑백 교대, GNU Go 계가):
  - RL vs GNU Go level 10: **40/40**
  - SL vs GNU Go level 10: 39/40
  - RL vs SL: 29/40 (72.5%, 95% 구간 59–86%)
- MCTS 400회에서 사전확률 비교 (가치는 양쪽 모두 SL 가치 head): RL 사전확률 대 SL 사전확률 16/30 (53%, 95% 구간 36–71%), **차이 없음**.
  정책 단독으로는 RL이 72~79%로 앞서지만, 탐색을 붙이면 격차가 사라진다.
  원 논문(SL 사전확률이 더 좋았음)과도 다르다. 새 가치망과 1600회 탐색으로 다시 확인한다.

## MCTS 자가대국 반복 학습 운영 규칙 (2026-10-19)

- 1바퀴: 2,261판(병렬 이전 생성기) → search_finetune_20261019. 원래 공유 모델 상대 400회 50판 32승18패(64.0%, 95% 50.1~75.9%).
- 자가대국: 병렬 32판, 트리 재사용(100회 수만, 물려받은 방문 포함), 기권 없음. 25% 400회(학습용, 새 트리)/75% 100회. 기존 대비 학습 국면당 약 1.9배 빠름.
- 학습: 국면당 한 번에 정책(방문 분포, 전 국면)+소유권(전 국면)+가치(고정 무작위 1/20 국면) 업데이트.
  직전 바퀴 모델에서 이어 학습, 최근 바퀴 데이터를 함께 사용(슬라이딩 윈도), 사람 기보 16개/배치로 정책 망각 방지.
- 가치 1/20 비율은 유지하고 바퀴를 쌓아 판수를 늘린다. 기존 생성 가치 데이터(--gen-batch)는 바퀴마다 줄인다:
  1바퀴 16 → 2바퀴 8 → 3바퀴 4 → 4바퀴 이후 0~2 (검증 자가대국 가치 MSE가 악화되면 되돌림).
- 채택: 직전 바퀴 모델과 400회 50판. 원래 공유 모델과의 누적 비교도 함께 기록.
